Linux brush-up

The commands you'll use every day around containers

Why start with Linux?

Containers are just Linux processes
Most servers are headless Linux
Debugging a container means debugging Linux

Who am I running on?

uname prints kernel and system information

$ uname -a
Linux ol9 5.15.0-uek x86_64 GNU/Linux
$ uname -r           # kernel release only
$ uname -m           # architecture

fastfetch

A good-looking system summary in one command

$ sudo dnf install -y oracle-epel-release-el9
$ sudo dnf install -y fastfetch
$ fastfetch

The modern successor to neofetch: OS, kernel, CPU, memory and shell at a glance

More about the system

$ cat /etc/os-release    # distro and version
$ hostnamectl            # hostname, OS, kernel
$ whoami; id             # user, UID, groups
$ uptime                 # running time, load

What is a process?

A running program with its own ID: the PID

Every process has a PID and a parent PID
It runs as a user, with that user's permissions
PID 1 is the first process: systemd

Listing processes with ps

$ ps aux                 # every process
$ ps aux | grep httpd    # find one
$ ps -ef --forest        # parent and child tree
$ pgrep -a mysqld        # PIDs by name

top: a live task manager

$ top
# P  sort by CPU      M  sort by memory
# k  kill a PID       q  quit
$ htop       # friendlier, colorful

Stopping a process: signals

SIGTERM (15) asks nicely, so the app can clean up
SIGKILL (9) stops it instantly, no cleanup
SIGHUP (1) tells many daemons to reload config

Using kill

$ kill 4242              # SIGTERM
$ kill -9 4242           # SIGKILL
$ kill -HUP 4242         # reload
$ pkill -f php-fpm       # by name

Try SIGTERM first. docker stop works exactly the same way.

Memory and disk

$ free -h        # memory usage
$ df -h          # disk space per filesystem
$ du -sh *       # size of each folder here
$ lsblk          # disks and partitions

Network checks

$ ip a                   # interfaces and IPs
$ ss -tulpn              # who listens on which port
$ ss -tulpn | grep 3306
$ curl -I localhost      # quick HTTP check

Services and logs

$ systemctl status httpd
$ sudo systemctl enable --now sshd
$ journalctl -u httpd -f     # follow logs
$ tail -f /var/log/messages

Permissions

read 4, write 2, execute 1, for owner, group and others

$ chmod 644 index.php    # rw-r--r--
$ chmod +x deploy.sh
$ sudo chown -R apache:apache /var/www

How we deployed before Docker

A PHP project, XAMPP and a lot of hope

The PHP project

Install XAMPP, or LAMPP on Linux
Copy the project into htdocs
Import the SQL dump in phpMyAdmin
Tweak php.ini and httpd.conf by hand
It works!

"It works on my machine"

Then we tried production.

Meanwhile, on the server

$ sudo dnf install httpd php php-mysqlnd mariadb-server
# dev laptop: PHP 8.2, server repo: PHP 8.0
# missing extensions: gd, zip
# different paths, users and permissions

Problem 1: version drift

Every machine has slightly different PHP, MySQL and Apache versions. Code that runs on one breaks on another.

Problem 2: tied to one machine

The environment lives inside that OS: paths, config files, installed packages. Rebuilding it takes a day.

Problem 3: conflicts

Project A needs PHP 7.4, project B needs 8.2. Both want ports 80 and 3306.

Problem 4: tribal knowledge

Setup steps live in someone's head. "Oh, you also need to enable gd."

Problem 5: people and scale

New developers spend days matching versions
Upgrades happen in place, with no clean undo
Scaling means configuring every server by hand

Enter Docker

Ship the environment, not just the code

Docker in one sentence

Package your app with everything it needs, then run it the same way anywhere.

Image vs container

Image

A read-only template.

The recipe.

Container

A running instance of an image.

The dish.

One image, many containers

Virtual machine vs container

App
Guest OS + kernel
Hypervisor
Hardware
App + libraries
Container runtime
Shared host kernel
Hardware

No guest OS: megabytes instead of gigabytes, seconds instead of minutes

Under the hood

Namespaces: each container sees its own processes, network and files
cgroups: limit CPU and memory
Layered filesystem: images stack read-only layers

What is a running copy of an image called?

  1. A volume
  2. A container
  3. A network
  4. A Dockerfile

The image is the template. A container is a running copy of it.

Live demo

The same XAMPP setup, rebuilt with containers

The plan

NetworkMySQLPHP + ApacheCompose

Step 1: network and MySQL

$ docker network create phpnet
$ docker run -d --name db --network phpnet \
    -e MYSQL_ROOT_PASSWORD=root \
    -e MYSQL_DATABASE=appdb \
    -v dbdata:/var/lib/mysql mysql:8.0
$ docker logs -f db     # wait for: ready for connections

Step 2: the PHP page

<?php
$c = new mysqli("db", "root", "root", "appdb");
if ($c->connect_error) die($c->connect_error);
echo "MySQL " . $c->server_info . " / PHP " . PHP_VERSION;

The host name db works because both containers share phpnet

Step 3: the Dockerfile

FROM php:8.2-apache
RUN docker-php-ext-install mysqli pdo_mysql
COPY src/ /var/www/html/

Three lines replace a whole XAMPP install

Step 4: build and run

$ docker build -t myphp:1.0 .
$ docker run -d --name web --network phpnet \
    -p 8080:80 myphp:1.0
$ curl http://localhost:8080
MySQL 8.0 / PHP 8.2

Step 5: all of it in compose.yaml

services:
  web:
    build: .
    ports: ["8080:80"]
    volumes: ["./src:/var/www/html"]
    depends_on: [db]
  db:
    image: mysql:8.0
    environment: { MYSQL_ROOT_PASSWORD: root, MYSQL_DATABASE: appdb }
    volumes: ["dbdata:/var/lib/mysql"]
  phpmyadmin:
    image: phpmyadmin
    ports: ["8081:80"]
    environment: { PMA_HOST: db }
volumes:
  dbdata:

One command to rule them all

$ docker compose up -d --build
$ docker compose ps
$ docker compose logs -f web
$ docker compose down    # add -v to drop the data

The whole XAMPP stack in one reproducible file

Docker in depth

Commands, images, containers and volumes

Image commands

$ docker pull nginx:1.27
$ docker images
$ docker build -t app:1.0 .
$ docker tag app:1.0 me/app:1.0
$ docker push me/app:1.0     # after docker login

More image commands

$ docker history app:1.0     # layers and sizes
$ docker rmi app:1.0
$ docker image prune -a      # unused images
$ docker save app:1.0 -o app.tar
$ docker load -i app.tar     # offline transfer

docker run: the essentials

$ docker run -d --name web nginx        # background, named
$ docker run -p 8080:80 nginx           # host:container
$ docker run -e APP_ENV=dev nginx       # environment
$ docker run -it --rm ubuntu bash       # throwaway shell

docker run: production flags

$ docker run --restart unless-stopped ...
$ docker run -m 512m --cpus 1 ...       # cgroup limits
$ docker run --network phpnet ...
$ docker run -v data:/data ...          # volume

Managing containers

$ docker ps              # running
$ docker ps -a           # including stopped
$ docker stop web        # SIGTERM, then SIGKILL after 10s
$ docker start web
$ docker rm -f web
$ docker cp web:/etc/nginx/nginx.conf .
$ docker system df       # disk usage

Dockerfile instructions

FROM php:8.2-apache            # base image
WORKDIR /var/www/html          # working folder
RUN docker-php-ext-install zip # build-time command
COPY . .                       # files from host
ENV APP_ENV=prod               # environment variable
EXPOSE 80                      # documents the port
CMD ["apache2-foreground"]     # default start command

Layers and the cache

COPY . .
RUN composer install
COPY composer.json
RUN apt-get install
FROM php:8.2-apache

Each instruction is a cached layer. Change one, and only it and the layers above it rebuild.

Building images well

Copy dependency files before source code
Chain RUN commands and clean caches
Use .dockerignore for .git, node_modules, .env
Pin versions, avoid latest in production
One main process per container

Container lifecycle

docker run is create plus start

CreatedRunningStoppedRemoved

Inside a container

A thin writable layer on top of the image
docker rm deletes that layer and its data
The main process is PID 1. When it exits, the container stops.

Volumes: data that survives

Containers are disposable. Your database is not.

Named volumes

Managed by Docker. Best for databases.

$ docker volume create dbdata
$ docker run -v dbdata:/var/lib/mysql mysql:8.0
$ docker volume ls
$ docker volume inspect dbdata

Bind mounts

A host folder mapped inside. Best for live code.

$ docker run -v $(pwd)/src:/var/www/html \
    -p 8080:80 php:8.2-apache
# edit on the host, refresh the browser

tmpfs and cleanup

$ docker run --tmpfs /tmp ...       # memory only
$ docker volume rm dbdata
$ docker volume prune               # unused volumes

Prove it

$ docker rm -f db
$ docker run -d --name db -v dbdata:/var/lib/mysql \
    -e MYSQL_ROOT_PASSWORD=root mysql:8.0
# the tables are still there

Debugging containers

Logs, shells, inspection and common failures

Start with the logs

Whatever the app prints to stdout and stderr

$ docker logs web
$ docker logs -f --tail 100 web
$ docker logs --since 10m web
$ docker compose logs -f

Get inside with exec

$ docker exec -it web bash          # or sh on alpine
$ docker exec web cat /etc/hosts
$ docker exec -it db mysql -uroot -p

Look closer with inspect

$ docker inspect web
$ docker inspect -f '{{.State.ExitCode}}' web
$ docker inspect -f '{{.Mounts}}' web
$ docker port web

Watch it live

$ docker stats          # CPU and memory per container
$ docker top web        # processes inside
$ docker events         # what the daemon is doing
$ docker diff web       # files changed vs the image

When it keeps crashing

Exit 137: killed, often out of memory
Exit 1: application error, read the logs
Exit 0: the main process finished on its own
$ docker run -it --entrypoint sh myphp:1.0   # bypass CMD

Common failures

Port allocatedss -tulpn, then pick another host port
Can't reach DBSame network? Use the service name
Mount deniedUID mismatch or SELinux
Changes missingRebuild with --build or bind mount
Disk fulldocker system df, then prune

Wait until the DB is ready

  db:
    image: mysql:8.0
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 5s
      retries: 10
  web:
    depends_on:
      db: { condition: service_healthy }
08

SELinux and Podman

How containers behave on Oracle Linux 9

What is SELinux?

Mandatory access control. Every file and process has a label, and policy decides who can touch what, even root.

chmod 777 and still denied?

Classic permissions say yes. SELinux says no. Both must allow the access.

SELinux modes

$ getenforce
Enforcing
$ sestatus
$ sudo setenforce 0     # Permissive, testing only

Fix the label. Never disable SELinux in production.

Labels, also called contexts

user : role : type : level. The type matters most.

$ ls -Z /var/www/html
system_u:object_r:httpd_sys_content_t:s0 index.php
$ ps -eZ | grep httpd
system_u:system_r:httpd_t:s0  1234  httpd

Finding denials

$ sudo ausearch -m avc -ts recent
$ sudo dnf install -y setroubleshoot-server
$ sudo sealert -a /var/log/audit/audit.log

Fixing labels

$ sudo restorecon -Rv /var/www/html
$ sudo semanage fcontext -a -t httpd_sys_rw_content_t \
    "/var/www/html/uploads(/.*)?"
$ sudo restorecon -Rv /var/www/html/uploads
$ sudo setsebool -P httpd_can_network_connect_db on

SELinux and container volumes

$ podman run -v ./src:/var/www/html php:8.2-apache
# Permission denied: files are labelled user_home_t
$ podman run -v ./src:/var/www/html:Z ...   # private
$ podman run -v ./shared:/data:z ...        # shared

Never use :Z on system folders like /home or /etc

Meet Podman

Oracle Linux 9 ships Podman, not Docker. Same images, same commands, no daemon.

Installing Podman

$ sudo dnf install -y container-tools  # podman, buildah, skopeo
$ podman run -d -p 8080:80 docker.io/library/nginx
$ sudo dnf install -y podman-docker    # docker calls podman

Docker vs Podman

Pods, Kubernetes and compose

$ podman pod create --name app -p 8080:80
$ podman run -d --pod app mysql:8.0
$ podman kube generate app > app.yaml
$ podman compose up -d

Quadlet files in /etc/containers/systemd run containers as services

A container keeps crashing. What do you check first?

  1. Restart the computer
  2. Reinstall Docker
  3. Delete the image
  4. docker logs

The logs usually show the error straight away.

Which container tool comes with Oracle Linux 9?

  1. Podman
  2. VirtualBox
  3. XAMPP
  4. Notepad

Podman runs the same images with the same commands, without a daemon.

On Oracle Linux, what can block access even after chmod 777?

  1. The keyboard layout
  2. The screen saver
  3. SELinux
  4. The time zone

Mount volumes with :Z or :z so SELinux lets the container use them.
